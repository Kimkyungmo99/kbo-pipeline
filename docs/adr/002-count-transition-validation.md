# ADR 002 — 볼카운트 전이 검증: 도메인 규칙을 품질 게이트로

날짜: 2026-08-25 · 상태: 채택 (핵심 ADR)

## 결정

투구 시퀀스의 볼카운트 전이가 야구 규칙과 일치하는지 전수 검증한다. 타석 내 합법 전이는 세 가지뿐이다: 볼 +1, 스트라이크 +1, 변화 없음(2스트라이크 파울·인플레이). 카운트 감소는 새 타석 시작이며, 새 타석의 첫 상태는 0-0·0-1·1-0만 허용한다.

## 왜 seq 어서션만으로는 부족한가

`pitch_seq_in_game`은 파싱 시 우리가 부여하는 번호다. 따라서 seq 연속성 어서션은 **파서가 흘린 행**만 잡고, **소스가 애초에 빠뜨리거나 순서를 바꾼 것**은 잡지 못한다. 소스 쪽 문제를 잡을 수 있는 것은 데이터에 내장된 도메인 규칙뿐이다. 두 검증은 서로 다른 실패 모드를 커버하므로 둘 다 유지한다.

## 실제로 잡은 것 (첫 실행, 2026-08-24, 3개 파티션 ~3,900투구)

불법 전이 2건이 나왔고, 원인 추적 결과:

1. **파서 버그 발견·수정** — 소스의 textRelays는 웹 표시 순서(최신 먼저, `no` 내림차순)로 온다. 파서가 응답 순서대로 seq를 부여해 **이닝 내 투구 순서가 시간 역순**이었다. 타석 내부는 순서가 맞아 다른 검증은 전부 통과했고, 타석 도중 대타 교체로 한 타석이 두 relay로 쪼개진 케이스에서만 꼬리가 잡혔다. 이 검증이 없었다면 변환·분석 단계까지 몰랐을 결함이다. (수정: `no` 오름차순 정렬)

2. **소스 오기장 1건 격리** — 몸에 맞는 볼 순간 카운트가 2-2→4-2로 +2 점프 (원 소스 웹에서도 동일). 동일 상황의 다른 HBP 6건이 전부 +1이므로 규칙이 아닌 단발성 기록 오류로 결론. 대응은 수정이 아니라 감지·기록이다.

## 검증 과정에서 확보한 도메인 지식

- **HBP는 pitchResult='B'로 기록된다** (7건 전수 확인). 타석 결과는 pitchResult가 아니라 타석 종료 텍스트("OOO : 몸에 맞는 볼")로 판정해야 한다. 3볼 카운트의 HBP는 투구 데이터만으로 볼넷과 구분 불가.
- **타석 도중 대타 교체 시 한 타석이 두 relay로 분할**된다. 타석(pa) 경계 판정은 relay 경계가 아니라 카운트 리셋 기준이어야 한다.
- currentGameState는 투구 직후 상태다 (ADR 예정인 시점 정합 처리와 연결 — dbt staging에서 직전 상태로 shift).

## 결과

경기당 ~300투구 × 시즌 720경기 규모에서, 쿼리 하나로 파싱 누락·순서 오류·소스 이상을 상시 감지한다. 검증 규칙 자체도 도메인 지식으로 계속 다듬는다(알려진 예외: HBP 기록 관행, 격리된 소스 오기장). 비용 대비 효과가 이 프로젝트에서 가장 좋은 품질 장치다.

## 개정 1 (2026-09-13) — 730경기 225,419투구까지 운영한 결과

채택 후 3주간 2024 시즌 전체(정규·순위결정전·포스트시즌)를 백필하면서 이 검증이 잡은 것과, 그 과정에서 갱신된 결론을 기록한다.

### 잡은 것 (시간순)

1. **파서의 시간 역순 버그** (첫 실행) — 위 본문.
2. **소스 이상의 분류 체계 확립** (4월 백필, 133경기): 위반을 raw까지 추적해 소스 패턴을 넷으로 나눴다.
   - 투구 누락: pitchNum이 1,2,5,6처럼 결손 → 카운트 점프. 수정 불가 → 감지·기록
   - 동일 투구 중복: 같은 pitchNum·같은 내용이 relay에 두 번 → 파서가 제거
   - 타석 합침: 두 타석이 relay 하나에 합쳐지며 pitchNum이 1부터 재시작 (7월 발견)
   - 카운트 점프 단독: 위 누락의 표면 증상 — 첫 실행의 "단발성 오기장"은 사실 이 패턴이었다 (표본 12배에서 재분류)
3. **파서 dedup의 조용한 데이터 손실** (7월 백필, 2024-07-24 WOOB): 2번의 "중복 제거"가 3번의 "타석 합침"을 중복으로 오인해 **실제 투구를 삭제**하고 있었다. 삭제된 타석은 위반을 만들지 않으니 검증에 안 걸렸지만, 삭제가 *부분적*이었던 한 경기에서 (+1,+1) 전이와 "새 타석 2-2 시작"이 튀었다. raw를 열어 확인 → dedup 규칙을 "번호+내용+타자가 모두 같을 때만 중복, 번호 역행 시 새 타석"으로 교체 → 전체 재파싱으로 +18투구 복구 (소스 재요청 0회 — raw 보존의 실전 근거).
   - 수정 후 숨어 있던 소스 누락 2건이 새로 드러남 (삭제됐던 타석이 살아나며 그 타석의 1구 누락이 보이게 됨). 합계는 10건 그대로였지만 구성이 "전부 소스 쪽"으로 바뀌었다.

### 최종 성적 (2024 시즌 완주 시점)

- 225,419투구 중 불법 전이 **10건 (0.0044%)**, 전부 소스 투구 누락 계열. 파서 결함 0
- 4~10월 월별 신규 위반: 5, 1, 0, 4(→재파싱 후 재구성), 0, 0, 0 — 검증과 파서가 소스에 수렴함
- 포스트시즌 18경기 신규 0건

### 갱신된 결론

- "알려진 예외" 목록은 HBP 기록 관행 + **소스 패턴 4종**으로 확장. 이 중 파서가 고칠 수 있는 것(중복·합침)과 없는 것(누락)을 구분해 대응이 다르다.
- **검증이 통과해도 데이터 손실은 있을 수 있다** — 삭제된 타석은 위반을 만들지 않는다. 그래서 위반이 나왔을 때 "소스 탓"으로 넘기지 않고 raw까지 내려가는 절차(probe_game.py)를 표준으로 삼았다.
- 조사 도구가 파서 규칙을 복제하면 파서 수정 때 같이 어긋난다 (실제로 발생). 판정 로직은 파서 한 곳에만 두고 도구는 그것을 호출한다.
- dbt 이식 완료: staging 위의 dbt test로 옮기고 알려진 소스 이상 13건을 seed 예외 테이블로 관리한다. 새로운 위반뿐 아니라 기존 예외가 사라져 seed가 낡아진 경우도 실패한다.
